# Unity NullReferenceException 조기 감지 기법 조사

Unity에서 나는 NRE는 대개 네 곳에서 생깁니다. 인스펙터 연결 누락, 초기화 순서, 파괴된 객체, 플레이 사이에 남은 static 상태입니다. 컴파일러 하나로는 이 넷을 다 잡지 못합니다. 그래서 공식 · 커뮤니티 자료도 단계별로 나눠 막는 방식을 권합니다. 아래는 문제가 일찍 드러나는 단계부터 정리한 것입니다.

## 1. 코드를 쓰는 중: Unity 전용 정적 분석기

- **Microsoft.Unity.Analyzers**: Unity 객체에 아래 문법을 쓰면 Correctness(정확성) 오류로 표시합니다.
  - `??` (UNT0007), `?.` (UNT0008), `??=` (UNT0023), `is null` (UNT0029)
  - `GetComponent` 를 자기 객체에 부르면 `RequireComponent` 를 쓰라고 권하는 규칙(UNT0039)도 있습니다.
  - VS Code용 공식 Unity 확장에 함께 들어 있어서, 지금 쓰시는 VS Code에는 확장만 설치하면 됩니다. Rider는 같은 검사를 자체 기능으로 제공합니다.
- **이 문법들이 위험한 이유**: Unity는 `UnityEngine.Object` 의 `==` 를 재정의해서 "파괴됨"도 null로 판정합니다(이른바 fake null). 그런데 `?.` · `??` 는 이 재정의를 거치지 않습니다. 그래서 파괴된 객체가 null 검사를 통과하고, 나중에 예외가 납니다.
- **한계**: 위 분석기는 IDE 안에서만 돕니다. Unity 컴파일 단계(커밋 전 게이트)에서도 돌리려면 분석기 DLL을 `Assets` 에 넣고 `RoslynAnalyzer` 라벨을 붙여야 합니다. 적용 범위는 asmdef로 제한할 수 있습니다(Unity 매뉴얼).

## 2. Nullable 참조 형식(NRT): 효과는 일부만

- **설정 방법**: Unity 6.6 매뉴얼에는 컴파일러가 Roslyn이고 언어 버전이 C# 9.0이라는 것까지만 나옵니다. NRT를 켜는 방법은 공식 문서에 없습니다. 커뮤니티에서는 두 방법을 씁니다.
  - asmdef 옆에 `csc.rsp` 를 두고 `-nullable:enable` 을 적는다.
  - 파일마다 `#nullable enable` 을 적는다.
- **한계 1**: Unity API에는 nullable 표시가 없습니다. 그래서 `GetComponent` · `Find` 의 결과를 바로 써도 경고가 나지 않습니다.
- **한계 2**: `[SerializeField] Image _image = null!;` 패턴은 인스펙터로 연결하는 필드의 경고를 꺼 버립니다. 이 필드들이 Unity NRE의 가장 큰 원인이라, 정작 그 부분은 못 잡습니다.
- **정리**: 순수 C# 로직(웨이브 계산, 데이터 구조) asmdef에서는 효과가 좋습니다. MonoBehaviour의 인스펙터 연결은 3번이 맡아야 합니다.

## 3. 에디터에서 연결할 때: 직렬화 참조 검증 (효과가 가장 큼)

이 기능을 하는 Unity 공식 내장 도구는 찾지 못했습니다. 커뮤니티에서 쓰는 방법은 다음과 같습니다.

- **"필수" 표시 속성**: 비어 있으면 인스펙터에 오류를 띄웁니다.
  - NaughtyAttributes `[Required]` (MIT 라이선스, OpenUPM으로 설치)
  - unity-notnullattribute (유지보수 중단)
  - Better Validation
  - Odin Validator는 유료라 G-02에 따라 쓸 수 없습니다.
- **프로젝트 전체 스캔**: EditMode 테스트로 모든 프리팹 · 씬을 돌면서 `SerializedObject` 의 ObjectReference 속성을 검사합니다. 판정은 이렇게 합니다.
  - `objectReferenceValue == null` 이고 `objectReferenceInstanceIDValue != 0` 이면 **Missing**(연결했던 대상이 지워짐)
  - `objectReferenceValue == null` 이고 ID가 0이면 **None**(처음부터 연결 안 함)
  - `GetComponents` 결과에 null이 있으면 스크립트가 빠진 컴포넌트(Missing Script)
- **`OnValidate`**: 빈 필드를 `TryGetComponent` 로 자동으로 채울 수 있습니다. 다만 열리지 않은 씬은 다시 열어 저장하기 전까지 호출되지 않습니다.
- **`[RequireComponent]`**: 컴포넌트를 붙이는 순간에만 확인합니다. 이미 배치된 인스턴스에는 소급 적용되지 않습니다.
- **빌드에서만 나는 NRE**: 씬이 Build Settings에 빠졌거나, 참조하는 에셋이 `Editor` 폴더 안에 있는 경우가 흔합니다.

## 4. 실행 직후: 바로 실패하게 만들기(fail-fast)

- **필수 의존성을 if로 감싸지 않기**: 공식 매뉴얼의 NRE 페이지는 "null 검사 또는 try/catch"를 권합니다. 그런데 필수 의존성을 `if (x != null)` 로 감싸면 연결 실수가 조용히 숨습니다. 필수 참조는 `Awake` 에서 한 번 검사하고, 비어 있으면 `Debug.LogError(msg, this)` 로 바로 크게 실패시키는 편이 낫습니다. 콘솔에서 로그를 클릭하면 해당 객체가 하이라이트됩니다.
- **`UnityEngine.Assertions.Assert.IsNotNull`**: 기본적으로 개발 빌드에만 들어가고 릴리스 빌드에서는 빠집니다(`UNITY_ASSERTIONS` 심볼, `BuildOptions.ForceEnableAssertions`).
- **선택적 컴포넌트**: `TryGetComponent` 로 "없을 수 있음"을 코드에 드러냅니다.

## 5. static 상태: Enter Play Mode 옵션

- 도메인 리로드(Domain Reload)를 끄면 static 필드와 static 이벤트 구독이 플레이 세션 사이에 남습니다. 그러면 이미 파괴된 객체를 가리키게 됩니다.
- Unity 문서의 처방은 `[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]` 로 static을 직접 초기화하는 것입니다.
- Project Auditor의 Domain Reload 화면이 이런 문제가 있는 코드를 찾아 줍니다. 검색 결과로는 Unity 6.4부터 에디터에 내장되어 있고, 그 이전 버전은 패키지로 설치합니다.

## 6. 빌드 게이트

- `IPreprocessBuildWithReport` 에서 3번의 검증을 돌리고, 문제가 있으면 `BuildFailedException` 을 던집니다.
- 일반 `Exception` 으로는 빌드가 멈추지 않는다는 포럼 답변과 이슈 트래커 기록이 있습니다.

## Defense 에 적용한다면 (제안)
